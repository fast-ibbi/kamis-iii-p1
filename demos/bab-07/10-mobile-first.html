Kenapa Mobile-First

Mobile-first bukan soal selera. Ia soal ke mana kaskade bergerak: dari gaya dasar untuk layar kecil, lalu naik menambahkan yang perlu. Pola sebaliknya menulis gaya desktop lebih dulu, lalu membatalkannya satu per satu.

Gaya dasar buat layar kecil

Gaya dasar berlaku untuk semua layar, termasuk HP. Setelah itu setiap media query hanya memuat bedanya — pada contoh ini cuma jumlah kolom, karena gap sudah diwarisi dari gaya dasar.

.kotak-uji {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}

@media (min-width: 576px) {
  .kotak-uji {
    grid-template-columns: repeat(2, 1fr);
  }
}

Kedua bingkai di atas disusun bertumpuk supaya sama-sama muat di kolom baca. Yang berbeda bukan jendela browser, melainkan lebar wadah yang digambarkan: bingkai pertama mewakili layar 375 px, bingkai kedua 768 px.

Gaya tambahan ditumpuk, bukan dibatalkan

@media (min-width: 992px) {
  .kotak-uji {
    grid-template-columns: repeat(3, 1fr);
  }
}

Blok kedua hanya menambah satu aturan. Gaya dasar tidak pernah ditulis ulang, jadi tidak ada aturan lama yang perlu dibatalkan. Kodenya bergerak naik seperti jalan kecil yang diperlebar: 1 kolom, lalu 2, lalu 3.

Di 768 px, satu gap 12 px menyisakan 756 px untuk dua kolom.

Tiap kartu selebar 378 px — lega, karena memang hanya dua kolom.

Pola yang dibatalkan satu per satu

Pola desktop-first menulis gaya layar lebar lebih dulu, lalu memakai max-width untuk membatalkannya di layar kecil. Kaskadenya berubah jadi tempat berburu bug: setiap pengecualian harus diingat, dan urutan penulisannya menentukan hasil.

.kotak-uji-desktop {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 12px;
}

@media (max-width: 575px) {
  .kotak-uji-desktop {
    grid-template-columns: 1fr;
  }
}

Pada kaskade Bab 3, kalau spesifisitasnya sama, aturan yang ditulis paling akhir menang. Itu sebabnya pola max-width mudah goyah: hasil akhirnya bergantung pada urutan penulisan, bukan pada niat penulisnya. Pendekatan mobile-first juga yang dipakai Bootstrap, jadi perpindahan ke Bab 9 nanti terasa mulus.

Inti pembelajaran: tulis dulu gaya yang masuk akal untuk layar kecil, lalu naikkan dengan min-width. Media query cukup memuat bedanya, jadi bloknya pendek dan kaskadenya tumbuh, bukan bertabrakan.
