Debugging CSS di DevTools

Di sini kita berhenti menebak dan mulai membaca: aturan mana yang menang, kenapa menang, dan di file mana aturan itu berasal. Panel Styles menunjukkan semua aturan dan mencoret yang kalah; panel Computed menunjukkan nilai akhir yang benar-benar menyala.

Dua panel, dua pertanyaan

PanelYang ditunjukkan
StylesSemua aturan, yang kalah tampil tercoret
ComputedNilai akhir yang benar-benar menyala

Contoh: satu elemen, dua aturan

Aturan pelajaran untuk membaca panel: satu panel bergaya DevTools, aturan yang kalah dicoret, aturan yang menang ditebalkan.

.panel-devtools {
  padding: 12px;
  border: 1px solid #d1d5db;
  border-radius: 6px;
  background: #ffffff;
  font-family: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace;
  font-size: 13px;
}

.aturan-kalah {

  text-decoration: line-through;
}

.aturan-menang {
  color: #111827;
  font-weight: 600;
}

  margin: 0;
  padding: 0;

.card-produk-title { font-size: 22px; } div .card-produk-title { font-size: 20px; } .produk-card .card-title { font-size: 1.25rem; }

Aturan yang tercoret bukan aturan yang salah — ia hanya kalah. Yang perlu kamu baca adalah sebab kekalahannya.

Empat langkah, satu hipotesis per putaran

  1. 1 · pertanyaan — kenapa elemen tampil begitu
  2. 2 · reproduksi — temukan syarat cacat, ambil tangkapan layar
  3. 3 · isolasi — pilih elemen terkecil yang gagal
  4. 4 · verifikasi ulang — satu hipotesis, satu perubahan

Menambah !important sebagai jawaban pertama adalah kebiasaan yang menyimpan regression. Satu perubahan per putaran itulah yang bikin kamu masih tahu penyebabnya saat hasilnya berubah; empat langkah ini terasa berat di cacat pertama dan jadi instan di cacat kesepuluh.
