Membaca Specificity: Pasangan Tiga Angka

Specificity dinilai sebagai pasangan tiga angka (id, class, elemen). Ketiganya dibaca sebagai tiga tingkat, bukan satu bilangan yang dijumlahkan.

Tangga specificity

Setiap tingkat menang atas tingkat di bawahnya. Satu angka id selalu mengalahkan berapa pun jumlah class.

TingkatPenulisanNilainya
paling lemahp(0, 0, 1)
.note atau :hover(0, 1, 0)
p.note — elemen + class(0, 1, 1)
#pengumuman(1, 0, 0)
tertinggistyle="color: #DC2626" pada elemeninline

Laboratorium kaskade

Tiga aturan berikut menyasar paragraf dengan kekuatan berbeda. Paragraf pertama hanya kena selector elemen, paragraf kedua kena class, paragraf ketiga kena kombinasi id, class, dan elemen.

/* Aturan 1: hanya menyasar elemen p, specificity (0, 0, 1) */
p {
  color: #334155;
}

/* Aturan 2: class menang atas selector elemen, (0, 1, 0) */
.note {
  color: #F59E0B;
}

/* Aturan 3: kombinasi id, class, dan elemen, (1, 1, 1) */
p#pengurusan.note {
  color: #16A34A;
}

Paragraf biasa — tinta #334155 dari aturan 1.(0, 0, 1)

Paragraf ber-class note — amber dari aturan 2.(0, 1, 0)

Paragraf ber-id pengurusan dan ber-class note — hijau dari aturan 3.(1, 1, 1)

Paragraf yang sama ditambah gaya inline — merah, menang atas aturan id.inline

Paragraf keempat adalah satu-satunya yang memakai gaya inline, dan itu khusus untuk demonstrasi — bukan pola proyek. Di panel Styles DevTools, aturan yang kalah akan tercoret, jadi kamu bisa menelusuri pemenangnya langsung.

Kalau Aturan 1 dan Aturan 2 ditukar posisinya, hasilnya tidak berubah. Bukan urutan yang menentukan, melainkan specificity: class selalu menang atas selector elemen.

Menghitung sendiri

Untuk p#pengurusan.note: satu id, satu class, satu elemen — (1, 1, 1). Untuk #navigasi ul li a.tautan: satu id, satu class, tiga elemen — (1, 1, 3).

Inti pembelajaran: specificity menentukan pemenang sebelum urutan penulisan dipakai.
