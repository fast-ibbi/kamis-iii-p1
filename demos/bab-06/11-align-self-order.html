align-self dan order: Pengecualian di Tingkat Anak

Dua properti terakhir di level anak tidak mengurus ukuran, melainkan penyimpangan kecil dari keputusan wadah. Keduanya ditulis pada anak, dan keduanya sebaiknya dipakai hemat.

align-self — satu item boleh melanggar perataan wadah

.kartu-unggulan {
  align-self: stretch;
}

Wadah di halaman ini memakai align-items: center, jadi semua kartu berdiri di tengah secara vertikal. Kartu yang diberi align-self: stretch keluar dari aturan itu dan meregang setinggi wadah, tanpa mengubah posisi dua kartu lainnya.

Nilainya sama dengan yang dipakai align-items — stretch, flex-start, flex-end, center, baseline — ditambah auto yang berarti ikut wadah. Berikut varian yang menempel di dasar wadah.

.kartu-dasar {
  align-self: flex-end;
}

order — mengubah urutan visual saja

.keranjang-dahulu {
  order: -1;
}

.menu-akhir {
  order: 1;
}

Item diurutkan berdasarkan nilai order. Nilai bawaannya 0, dan angka kecil mendahului angka besar. Di bawah, kartu nomor 3 diberi order: -1 sehingga tampil paling kiri, sedangkan kartu nomor 1 diberi order: 1 sehingga tampil paling kanan.

1 · order 1tampil terakhir
2 · order 0tampil di tengah
3 · order -1tampil pertama

Yang berubah hanya urutan visual. Urutan dokumen HTML tetap 1, 2, 3, dan pembaca layar serta tombol Tab mengikuti urutan dokumen itu, bukan urutan yang terlihat di layar.

Kenapa ini soal disiplin, bukan cuma soal teknis

  • Pengguna pembaca layar mendengar urutan yang berbeda dari yang dilihat mata, sehingga bisa tersesat.
  • Fokus keyboard melompat tidak sesuai arah baca di layar.
  • Aturan yang aman: urutan dokumen selalu dibuat logis lebih dulu, baru CSS menyesuaikan sedikit.
  • order untuk penyesuaian kecil, bukan untuk menyusun ulang seluruh konten.

Inti pembelajaran: align-self dan order sama-sama ditulis pada anak dan sama-sama mengalahkan keputusan wadah. Keduanya berguna justru karena jarang dipakai; kalau terlalu banyak, layout berhenti bisa dibaca dari HTML-nya.
